# Measurements - 2026-08-17

> **Read this first.** Every utilization and cost figure below is a floor, not a measurement,
> while [#27](https://github.com/thousandflowers/skillreaper/issues/27) and
> [#28](https://github.com/thousandflowers/skillreaper/issues/28) are open. #27: every `mcp`
> row carries `Tokens=0` and `DeadToolChars=0`, so no MCP tool-schema weight enters
> `DeadTokensPerSession` or `MoneyPerMonth` - the cost shown is skills + agents + prose only.
> #28: remote claude.ai connector servers produce no row at all, so 16 servers that were
> present in this machine's context, one of which fired, are absent from both the loaded and
> the fired side of the `mcp` counts. Real usage is higher than what these numbers report, and
> real cost is higher too. Until both issues close, read "1–2% utilization" as *at most this
> good, over the categories reap can currently see*.

Read-only measurement session. Sections A and the version comparison come from `reap`;
sections B, C and D come from `gh` and are not affected by any reap version.

Rule applied: every number below is either a field read from `reap --json` output or the
output of a named command. Nothing is estimated or derived by hand. Where a figure is not
readable from a field or a command, it is marked **non disponibile**.

### A.9 MCP tool-name prefix forms, and what the fix changed

Extracted from the real corpus (36 `.jsonl`, 279M in `~/.claude/projects`):

- `grep -ho '"name":"mcp__[^"]*"' | sort -u` → **6** distinct tool names actually invoked.
- `grep -hoE 'mcp__[A-Za-z0-9_.-]+__' | sort -u` → **37** distinct server prefixes, counting
  tool *declarations* injected into system prompts, not just invocations.

Three real forms, plus fixture noise:

| form | example | server segment recorded | has a row? |
|---|---|---|---|
| `mcp__<server>__` | `mcp__headroom__headroom_stats` | `headroom` | yes |
| `mcp__plugin_<plugin>_<server>__` | `mcp__plugin_ecc_playwright__browser_navigate` | `plugin_ecc_playwright` | **only after the fix** |

`mcp__claude-in-chrome__` follows form 1 but has no row either. `mcp__{server,srv,fetch,rare,empty}__`

The fix, isolated against the same corpus (HEAD pre-fix → HEAD+fix, runs 74 seconds apart):

```
diff <(jq -r '.Rows[]|"\(.Category)/\(.Name)\t\(.Uses)\t\(.Verdict)"' reap-head.json|sort) \
     <(jq -r '.Rows[]|"\(.Category)/\(.Name)\t\(.Uses)\t\(.Verdict)"' reap-after.json|sort)

> mcp/chrome      2  KEEP          # row did not exist before
< mcp/playwright  0  REAP
> mcp/playwright  3  KEEP
```

Exactly two rows change. Two distinct root causes were behind them:

1. **Prefix join.** `internal/usage/usage.go` records the segment between `mcp__` and the next
   `__`, so a plugin server lands under `plugin_<plugin>_<server>`, while
   `internal/report/report.go` joined on the bare scanned name. All six `plugin:ecc@ecc`
   servers were affected; `playwright` is the one with provable calls.
2. **Manifest-declared servers.** `internal/scan/mcp.go` read only a plugin's `.mcp.json`.
   `superpowers-chrome` declares `mcpServers` inline in `.claude-plugin/plugin.json`, so its
   `chrome` server produced no row at all - invisible rather than miscounted.

### B.1 How they were found, and the search criteria

Starting point given by the request: `deadskills`.

1. `gh search repos deadskills --limit 10 --json fullName,stargazersCount,description,updatedAt`
   → 4 hits, of which one relevant: `anandsaini18/deadskills`. The other three are a Unity
   game-jam entry and two GitHub Classroom repos.
2. `gh search repos "<multi-word query>"` returned empty result sets for most queries
   (e.g. `unused skills claude code`, `prune skills agent`, `mcp tools unused audit` → `[]`),
   so the sweep was redone against the REST search endpoint directly:
   `gh api -X GET /search/repositories -f q='<query>' -f sort=stars -f per_page=N`.
3. 18 further queries were run against `/search/repositories`, sorted by stars:
   `skills unused claude` · `claude-code skills prune` · `skill pruning` ·
   `unused MCP servers` · `claude code context bloat` · `skill audit claude code` ·
   `agent context audit` · `claude skills usage` · `reap skills` · `skill graveyard claude` ·
   `claude code hygiene skills` · `which skills do I actually use` · `subagents unused audit` ·
   `transcript usage skills claude` · `context diet claude code` · `skills token cost audit` ·
   `claude code setup audit cli` · `disable unused skills`
4. Inclusion criterion applied to the union of hits: the repo's own description says it
   **audits, measures, or prunes the installed agent stack** - skills, MCP servers, subagents,
   hooks, or always-loaded prose - for a coding agent. Excluded: source-code dead-code
   scanners (`vibealive`, `vtrigger`, `xcode-janitor-mcp`), context-compression proxies and
   hooks that never enumerate the stack (`ctx-diet`, `LLM_DIET`, `honey-for-devs`), skill
   installers/syncers with no usage evidence (`sync-skills`), and name collisions
   (`bug-reaper`, `WebReaper`, REAPER-DAW skills, `Sorax5/DeadSkills`).
   Included but flagged as dashboards rather than pruners: `tokenscope`, `cc-usage-dashboard`,
   both `claude-code-token-audit` repos.
5. Per-repo metadata read with:
   - stars / open issues / archived / language: `gh api /repos/<full_name>`
     (`.stargazers_count`, `.open_issues_count`, `.archived`, `.language`)
   - last commit: `gh api /repos/<r>/commits?per_page=1` → `.[0].commit.committer.date`
   - first commit: `gh api -i /repos/<r>/commits?per_page=1`, read the `page=` value out of the
     `Link: …rel="last"` header, then fetch that page → `.[0].commit.committer.date`
   - open PRs: `gh api /repos/<r>/pulls?state=open&per_page=100 --jq 'length'`

Caveat on the open-issues column: GitHub's `open_issues_count` **includes open pull requests**.
The open-PR count is listed separately so the two can be separated.

## Discrepancies with the audit

Each line states the assumed figure, the measured figure, and the field or command that

1. **"5 items out of 376" → no run produces those numbers.**

2. **"1% utilization" was true of one snapshot only.**
   `reap gap` printed `total 378 7 1%` at 17:06. The **same binary** re-run at 18:11 prints
   `total 378 8 2%`, and HEAD+fix prints `total 379 10 2%`. The audit quoted a moment, not a
   property.

3. **The binary version turned out not to be the explanation for anything.**
   Homebrew `v0.5.0` and the `a45fba5` build produce byte-identical rows and identical
   `DeadCount` / `DeadTokensPerSession` / `MoneyPerMonth` on the same corpus. The 14 commits

4. **The transcript corpus drifts under you, and that is what moved the numbers.**
   `skill/graphify` reads `Uses=0 / REAP / LastUsed=0001-01-01T00:00:00Z` in the 17:06 dump and
   `Uses=13 / KEEP / LastUsed=2026-08-17T15:48:09.467Z` in every later dump, including from the
   unchanged Homebrew binary. Any measurement of this stack needs its `GeneratedAt` quoted
   alongside it.

5. **`.Rows` and `.Gap` count different populations.** `.Gap` excludes the 22 `prose` rows and
   the 1 `hook` row in every run. Any "N items scanned" claim has to say which field it came
